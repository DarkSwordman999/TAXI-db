# TAXI DB

База данных PostgreSQL на **реальных поездках такси Чикаго**. Данные ежедневно собираются из открытого API города через GitHub Actions, загружаются в базу и анализируются SQL-запросами, представлениями, функциями PL/pgSQL, Python-отчетами и графическим интерфейсом.

## Источник данных

[Chicago Data Portal — Taxi Trips](https://data.cityofchicago.org/resource/ajtu-isnz.json) (набор `ajtu-isnz`): все поездки лицензированных такси города, которые публикует мэрия Чикаго. Город обезличивает данные: машина указана хэшем `taxi_id`, о пассажире известен только способ оплаты, время округлено до 15 минут, места — до района (community area). Публикация идет с задержкой около двух недель.

Что делает проект:

- `parser/chicago_fetch.py` скачивает поездки по дням: для каждого дня — выборка из 2000 поездок, упорядоченных по `trip_id`. `trip_id` — случайный хэш, поэтому выборка равномерная и при повторном запуске та же самая. Явный брак (нулевые и невозможные поездки) отсеивается при загрузке из API.
- Каждый день хранится отдельным файлом `data/chicago/rides/ГГГГ/ГГГГ-ММ-ДД.csv.gz` (около 80 КБ), поэтому данные лежат прямо в репозитории и любой клон получает ту же базу.
- `.github/workflows/parser.yml` запускает сборщик каждый день и коммитит новые файлы.
- `parser/load_rides.py` загружает файлы в базу. Повторный запуск добавляет только новые поездки.

Суммы — в долларах США, расстояние переведено из миль в километры.

## Технологии

PostgreSQL (SQL, PL/pgSQL), Python 3 (psycopg2, matplotlib, Tkinter), Bash, GitHub Actions.

## Быстрый запуск

```bash
createdb taxi
python3 -m pip install -r requirements.txt
./help.sh rebuild        # схема, справочники и все поездки из data/chicago/rides
./help.sh task1          # выручка по сезонам
./run_app.sh             # графический интерфейс
```

Обновить данные после `git pull` (новые дни, собранные GitHub Actions):

```bash
./help.sh load
```

Скачать недостающие дни самостоятельно, без GitHub Actions:

```bash
./help.sh fetch          # последние 45 дней
./help.sh fetch 365      # за год
./help.sh load
```

`./help.sh rebuild` пересоздает все таблицы: ручные изменения в базе пропадут.

## Конфигурация подключения

Настройки подключения задаются в одном месте — стандартными переменными PostgreSQL. Их читают GUI, Python-скрипты (через `app/scripts/db_config.py`) и shell-скрипты (через `psql`):

| Переменная | По умолчанию |
|---|---|
| `PGDATABASE` | `taxi` |
| `PGHOST` | `localhost` |
| `PGPORT` | `5432` |
| `PGUSER` | имя пользователя ОС |
| `PGPASSWORD` | пусто |

Если значения по умолчанию подходят, ничего настраивать не нужно. Иначе скопируйте `.env.example` в `.env` и укажите свои значения. Файл `.env` не попадает в git. Скрипты можно запускать из любой папки: они сами находят корень проекта.

## Структура базы данных

| Таблица | Назначение |
|---|---|
| `ТАКСОПАРКИ` | таксопарки Чикаго (поле `company` данных города) |
| `ВОДИТЕЛИ` | такси с водителем: обезличенный `taxi_id`. В Чикаго лицензия выдается на машину, поэтому водитель и машина в данных неразличимы |
| `КЛИЕНТЫ` | типы клиентов по способу оплаты: карта, наличные, приложение, предоплаченная карта и т. д. О пассажирах город больше ничего не сообщает |
| `РАЙОНЫ` | 77 районов Чикаго с координатами центра |
| `ПОЕЗДКИ` | поездки: время, водитель, тип клиента, таксопарк, районы посадки и высадки, километры, минуты, стоимость, чаевые, сборы |
| `СЕЗОН` | соответствие месяца сезону для аналитики |

Связи:

- `ПОЕЗДКИ.водитель` → `ВОДИТЕЛИ.код`;
- `ПОЕЗДКИ.клиент` → `КЛИЕНТЫ.код`;
- `ПОЕЗДКИ.таксопарк` → `ТАКСОПАРКИ.код`;
- `ПОЕЗДКИ.откуда`, `ПОЕЗДКИ.куда` → `РАЙОНЫ.код` (пусто, если поездка началась или закончилась за городом).

Водитель, клиент и таксопарк поездки обязательны (`NOT NULL`), удалить их, пока на них ссылаются поездки, нельзя (`ON DELETE RESTRICT`). `ПОЕЗДКИ.trip_id` уникален: одна и та же поездка не загрузится дважды. Таксопарки уникальны без учета регистра: в данных города одно название встречается в разном написании.

Индексы: по дате поездки и всем внешним ключам.

## SQL-команды

Основной запускатель SQL-команд: `./help.sh` (без параметров выводит полное меню).

### Данные

| Команда | Описание |
|---|---|
| `./help.sh fetch [дней]` | скачать недостающие дни из открытых данных Чикаго |
| `./help.sh load` | загрузить скачанные поездки в базу (только новые) |
| `./help.sh rebuild` | пересоздать базу и загрузить все поездки |

### Основные задачи

| Команда | Описание |
|---|---|
| `./help.sh task1` | выручка по сезонам |
| `./help.sh task2` | выручка по сезонам и таксопаркам |
| `./help.sh task3` | выручка по дням недели и водителям (топ-5 в каждый день) |
| `./help.sh task4 N` | выручка по водителям за день недели N (1 — пн ... 7 — вс) |

### JOIN и операции изменения данных

| Команда | Описание |
|---|---|
| `./help.sh 07` | INNER JOIN: поездки с таксопарком и водителем |
| `./help.sh 08` | LEFT JOIN: районы с наименьшим числом поездок |
| `./help.sh 09` | RIGHT JOIN: типы клиентов и их поездки |
| `./help.sh 10` | FULL JOIN |
| `./help.sh 11` | CROSS JOIN: таксопарки × типы клиентов |
| `./help.sh 12` | SELF JOIN: соседние районы |
| `./help.sh 60` - `./help.sh 65` | UPDATE и DELETE с состоянием до и после |

Демонстрационные скрипты в `queries/update`, `queries/delete`, `queries/insert` выполняются в транзакции с `ROLLBACK` и не меняют базу.

## Python-отчеты

Запускатель: `./python_reports.sh`.

| Команда | Описание |
|---|---|
| `./python_reports.sh 1 [код_водителя] [тип_клиента]` | выручка по водителям и типам клиентов |
| `./python_reports.sh 1s [код_водителя] [тип_клиента]` | то же со звездочкой в углу таблицы |
| `./python_reports.sh 2 [тип_клиента]` | сводные матрицы выручки и числа поездок |
| `./python_reports.sh 3` | график динамики выручки и числа поездок по месяцам |
| `./python_reports.sh 4 [код_водителя]` | круговая диаграмма выручки по типам клиентов |
| `./python_reports.sh save` | сохранить графики в `docs/` |
| `./python_reports.sh all` | выполнить все отчеты |

Без кода водителя отчеты показывают 15 водителей с наибольшей выручкой.

## Графический интерфейс

`./run_app.sh` запускает `app/gui.py`: дашборд, просмотр и фильтрация поездок (по таксопарку, водителю, типу клиента, районам, дате, сумме), рейтинги, аналитика по периодам, дням и часам, графики matplotlib, добавление и редактирование записей, триграммный поиск (`pg_trgm`), экспорт в CSV, резервная копия через `pg_dump`, запуск SQL-скриптов и всех команд `help.sh` и `python_reports.sh`.

## Примечания

- Имена таблиц и полей русские, поэтому терминал и редактор должны работать в UTF-8.
- Названия таксопарков и районов — как в данных города, на английском.
- Расписание GitHub Actions работает только из ветки по умолчанию; ручной запуск сбора — вкладка Actions → «Сбор поездок такси Чикаго» → Run workflow.
